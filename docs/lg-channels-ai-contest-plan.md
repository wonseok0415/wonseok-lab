> 몰입과 일관성을 동시에 잡는다. 인물이 있어야 '공감지능이 *누구를* 향하는가'가 보인다.

## 3. 20분 구성 (씬 단위 설계)

20분 = 1,200초. 영상 생성 AI는 5~10초 클립 단위 → **총 150~200컷 예상.**
**확장 흐름:** 한 사람의 하루를 따라 — 집 → 이동 → 일터 → 도시의 밤 → 귀가. 공간 스케일이 단계적으로 커지고, 마지막에 집으로 돌아와 아크가 닫힌다.

```
[ 오프닝 ]    0:00 - 1:00    빛이 깨어남 + 가족이 깨어나는 기척(손·실루엣) / (후반) 타이틀·슬로건
[ Ch.1 집 ]   1:00 - 6:00    The Home that Cares — 공간이 가족을 돌본다 [친밀 마크로]
                            아침. 부부+아이의 하루 시작, 집이 '보이지 않는 안무'로 응답. 👤앵커#1(주인공)
[ Ch.2 이동 ] 6:00 - 9:30    The Space that Moves — 슈필라움: 이동조차 또 하나의 거실 [흐르는 모션]
                            주인공과 아이가 차에 오름. 가변 라운지·ThinQ ON, 창밖 풍경이 흐름.
[ Ch.3 공간들 ]9:30 - 13:30  The Spaces in Concert — 하나의 집에서 수많은 공간으로 [리듬·기하·스케일]
                            ThinQ Pro(주거단지→오피스) + Hospitality(점심·레스토랑 서비스 로봇)까지.
[ Ch.4 도시 ] 13:30 - 18:00  The City in Tune — 지능이 도시 스케일로 [광활 항공, 순수 감정 클라이맥스]
                            도시의 밤, 주인공이 빛의 도시를 바라봄. (물류·제조는 엔딩 리빌로) 👤앵커#2
[ 연결+엔딩 ] 18:00 - 20:40  ⚙AXIUM 4영역 리빌 + Borderless(빛의 네트워크) + 귀가(아이가 달려옴) + 슬로건. 👤앵커#3
```

> 챕터 길이를 차등(집5·이동4·관리3.5·도시4.5분)해 단조로움을 피한다. 챕터 단위로 룩(컬러·조명)·시각 문법을 통일.

### 🔑 제작 규율 (페이스·전달력)

1. **FAST 자핑 훅:** 오프닝 **첫 10~15초**에 "공간=지능"의 강렬한 비주얼 한 방. 추상 데이터 서사는 그 *다음*에 푼다. (자핑 시청자 이탈 방지)
2. **마이크로 비트(micro-beat):** **약 90초마다** 미세 페이오프(빛의 반응·공간의 움직임·스케일 전환)를 배치해 20분의 단조로움을 깬다. → 씬 시트에 비트 단위로 표기.
3. **온스크린 텍스트(영어 단독, 후반 합성):** 인터타이틀(타이틀+챕터4+클로징) + **이해를 돕는 설명 자막**을 필요 구간마다 삽입. **모든 텍스트는 편집 단계에서 실제 폰트로 합성** — AI 영상은 글자를 '그리는' 방식이라 **영어도 움직임 중 흔들리고 깨진다**(Sora 2/Veo 3.1 공통 한계). 프롬프트엔 항상 `no text`.
4. **액추에이터 가시화:** "보이지 않는 안무"만으로는 *LG가 무엇을 만드는지* 전달되지 않는다. **각 챕터에 우아한 관절·구동 메커니즘 클로즈업 1컷 이상** + 엔딩 직전 전용 '메커니즘 리빌' 1회. 표면이 움직일 때 그 안의 정밀 액추에이터가 함께 보이도록 연출.
5. **가족 현존 + 감정 아크:** 가족(부부+아이)의 하루를 실로 깐다. **얼굴 앵커는 주인공 1인 × 3컷(👤)만**(고정 레퍼런스), 배우자·아이는 항상 얼굴 회피(손·뒷모습·실루엣) — **아이 얼굴 생성 금지**(왜곡 빈발·민감성). 아침 집→…→밤 도시→**귀가(아이가 달려와 안김)** 로 닫는다.
6. **챕터별 시각 문법 차등 + 템포 변화:** 집=친밀 마크로 / 이동=흐르는 모션 / 관리=리듬·기하·스케일 / 도시=광활 항공. 전환·⚙리빌·엔딩 몽타주에 **빠른 템포**를 섞어 균일한 슬로우 드리프트를 깬다.

### 🎯 "비가시적 인과"의 프롬프트 번역 규칙 (가장 중요한 제작 노하우)

AI 영상은 '온도·예지·0.3초 전' 같은 **비가시적 인과를 직접 못 찍는다.** 반드시 **시각 대리물**로 번역한다.

| 전달하려는 의미 | ❌ 직접 묘사 | ✅ 시각 대리물(프롬프트) |
|----------------|-------------|------------------------|
| 따뜻함/온도 상승 | "바닥이 데워진다" | warm amber glow spreading across the floor surface |
| 예지(미리 안다) | "일어서기 1초 전" | light gently flowing ahead toward the direction of movement |
| 환기/공기 조정 | "공기를 정화한다" | soft air particles drifting, curtains breathing subtly |
| 돌봄/감응 | "공간이 반응한다" | surfaces softly illuminating in response, ripple of light |

> 화면 내 **텍스트·자막·타이포·로고는 AI 생성 금지** → 모두 **후반 편집에서 합성**. 프롬프트엔 `no text` 명시.

### 챕터별 비주얼 가이드 (룩 통일용)

| 챕터 | 컬러·조명 | 핵심 모티프 |
|------|-----------|-------------|
| 오프닝 | 암전 → 따뜻한 화이트/앰버 + 시안 입자 | 빛 입자, 깨어남 |

| Ch.2 이동 | 실내 웜 + 창밖 흐르는 풍경광 | 슈필라움(가변 라운지), 파노라마 글래스, ThinQ ON 글로우 |
| Ch.3 관리 | 클린 화이트 + 자연광 + 그린 액센트 | 여러 공간이 한 호흡으로(다세대·빌딩), 관제=빛의 별자리 |

## 4. AI 프롬프트 작성 규칙 (★ STUDIO341 제출물)

프롬프트 자체가 제출 항목이므로 **재현 가능하게** 기록한다.

### 4-1. 표준 포맷
```
[Subject]   주제·피사체
[Scene]     배경·환경
[Camera]    샷 종류·움직임 (slow dolly-in, aerial orbit 등)
[Lighting]  조명·시간대 (golden hour, soft morning light)
[Style]     화풍·질감 (cinematic, anamorphic 50mm, photorealistic)
[Mood]      분위기 (serene, warm, awe)
[Tech]      16:9, FHD+, duration
[Negative]  배제 요소 (no text, no logos, no humans/distortion)
```

### 4-2. 고정 스타일 블록 (전 컷 재사용 → 톤 일관성)
```
cinematic, anamorphic 50mm lens, shallow depth of field, subtle lens flare,
soft volumetric light, subsurface scattering, warm amber + deep navy palette,
bioluminescent cyan light accents, photorealistic, ultra-detailed, 16:9, FHD+
```
### 4-3. 고정 네거티브 블록
```
no text, no captions, no logos, no humans (or backlit silhouette only),
no distortion, no warped geometry, no extra fingers, no watermark, no flicker
```

### 4-4. 기록 원칙
- 사용 도구·모델·버전·시드(seed)·파라미터 보존 → 재현성
- 채택 vs 폐기 프롬프트 구분, 후보정(업스케일·색보정) 단계도 기록

## 5. 제작 파이프라인 & 도구 전략 (회사 기획안 병합)

### 5-1. 단계별 도구 매핑
| 단계 | 작업 | 도구 | 비고 |
|------|------|------|------|
| 기획·프롬프트 설계 | 콘셉트·구성·프롬프트 변형 | **Claude (Chat)** | 이 문서 기준 적용 |
| 룩 기준 스틸 | 챕터별 키프레임 이미지(룩 통일) | **Midjourney / Firefly** | **컷 간 일관성의 핵심** — 스틸을 먼저 확정 |
| 영상 생성(주력) | 스틸 기반 image-to-video 대량 | **Kling 3.0** | i2v 일관성·물리(빛·물·천) 강점, 가성비(~$0.07/초) |
| 영상 생성(히어로) | 오프닝·⚙리빌·대형 항공 핵심 컷 | **Veo 3.1** | 최고 포토리얼(자연·건축). Fast($0.15/초) 드래프트→Standard 확정 |
| 카메라 정밀(선택) | 복잡한 카메라 무브 | **Runway Gen-4.5 / 힉스필드** | 카메라 제어·프리셋. MCP 원하면 힉스필드 |
| 음악 | BGM·환경음 | Suno / 라이선스 | **상업·방영 라이선스 필수 확인** |
| 자막·타이틀 | SRT·타이포 | **후반 편집 합성** | AI 생성 금지 |
| 편집·합성 | 컷편집·색보정·인코딩 | 편집툴 / `ffmpeg` | FHD+·16:9·20분+ 검증 |

### 5-2. 권장 운용 (우리 기획 최적화)
1. **룩 바이블 먼저:** Midjourney로 챕터별 키프레임 스틸을 고정 스타일로 생성 → 150컷 **일관성 리스크를 원천 차단**.
2. **주력 = Kling(i2v):** 스틸을 애니메이트(약 80% 컷). 저비용·강한 일관성·뛰어난 모션.
3. **히어로 = Veo 3.1:** 오프닝/⚙리빌/대형 항공 등 시그니처 컷만 (Fast 드래프트 → Standard 확정).
4. **카메라 정밀 컷:** 필요 시 Runway/힉스필드. 보정·재생성 여유분 확보.

> 💡 **Sora·네이티브 오디오 불필요:** 무대사·무내레이션 영상이라 음성·립싱크에 프리미엄 낼 이유 없음 → BGM·사운드는 후반에서.
> 💡 **힉스필드(MCP)는 '선택':** Claude에서 바로 생성·이터레이션하는 편의 + 카메라 프리셋이 장점이나, 품질은 결국 하위 모델(Veo/Kling)에 좌우. 처음이라면 각 툴 웹 UI가 더 직관적.
> ⚠️ 도구별 가격·MCP·크레딧 만료 정책은 **가입 직전 공식 페이지에서 재확인**(정책 변동 잦음). 크레딧 만료 리스크 → 본 제작 일정에 맞춰 구독.

> 반복/배치 작업(자막 SRT 생성, ffmpeg 합성·인코딩, 파일 일괄 정리)은
> Claude **Code** 환경에서 스크립트로 자동화 가능 (필요 시 이 저장소에 구축).
