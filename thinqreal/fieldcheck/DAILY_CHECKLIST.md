# ThinQ Real 일일 상태 점검 체크리스트 (수동)

> FieldCheck 자동 점검 시스템 가동 전까지, 운영관리자가 **매일 출근 직후(1회차 09:00 전)** 수행한다.
> 소요 시간 목표: **5분 이내.** 목적은 정밀 진단이 아니라 "오늘 시연 가능한가"의 조기 확인이다.

## 아침 점검 (총 6항목)

| # | 항목 | 방법 | 정상 기준 |
|---|------|------|----------|
| 1 | **기동어 응답** | 기동어 발화 → 간단한 질문 1개 (예: "지금 몇 시야?") | 3초 이내에 음성 응답 시작 |
| 2 | **일상 대화** | 자유 질문 1개 (예: "오늘 날씨 어때?") | 질문에 맞는 내용으로 응답 |
| 3 | **가전 제어** | 음성으로 조명 켜기 → 끄기 | 말로만 "켰다"가 아니라 **실제 조명이** 켜지고 꺼짐 |
| 4 | **루틴/모드 실행** | 시연 시나리오 중 루틴 1개 실행 | 루틴에 포함된 동작들이 실제 수행됨 |
| 5 | **응답 음질** | 위 1~4의 응답을 들으며 확인 | 끊김·중간 침묵·기계음 이상·비정상 속도 없음 |
| 6 | **당일 예약 확인** | 관리자 페이지 → 예약 관리 | 오늘 확정 예약 회차 파악, 특이사항(R&D/B2B 등) 확인 |

> 항목 5가 **ATOM TTS 장애(2026-07 사례)를 잡는 항목**이다. "응답은 하는데 음성이 이상하다/늦다"도 이상 징후로 취급할 것.

## 판정과 기록

- **6항목 모두 정상** → 기록만 남기고 종료 (✅ 정상)
- **하나라도 이상** → 아래 [이상 발생 시 대응] 수행

기록은 팀 공유 위치(예: 예약 관리 Sheets에 `daily_checks` 탭 추가, 또는 팀 노트)에 한 줄이면 충분하다:

```
날짜 | 점검자 | 결과(정상/이상) | 이상 항목 번호 | 증상 요약 | 조치
2026-07-30 | 홍길동 | 정상 | - | - | -
2026-07-31 | 홍길동 | 이상 | 1,5 | 발화 후 무응답 2회/5회 | 재현 확인 후 담당자 공유, SW 버전 임시 전환
```

매일 남긴 기록이 곧 장애 이력 데이터가 된다. **정상인 날도 반드시 기록**할 것 (무기록과 정상을 구분하기 위함).

## 이상 발생 시 대응 (순서대로)

1. **재현 확인** — 같은 동작을 2~3회 반복. 몇 회 중 몇 회 실패인지 세어둔다 (예: "5회 중 2회 무응답")
2. **시각 기록** — 최초 인지 시각을 기록한다 (장애 타임라인의 시작점이 된다)
3. **범위 확인** — 가능하면 다른 조건에서도 재현되는지 확인 (다른 질문, 다른 가전, 시간을 두고 재시도). 특정 기능만 문제인지, 전반적 문제인지 구분
4. **담당자 공유** — 이철호 책임 / 서문수 선임 / 김현진 선임에게 증상·시각·재현율 공유
5. **임시 조치 검토** — 당일 시연 예약이 있으면 우회 수단을 확보한다
   - 선례: TTS 장애 시 Microsoft TTS 서버를 사용하는 최신 SW 버전으로 전환하여 시연 진행 (2026-07 사례)
6. **기록 완결** — 조치 내용과 복구 시각까지 기록에 남긴다

## 예약 슬롯 직전 미니 체크 (선택, 30초)

당일 확정 예약이 있는 회차는 **시작 30분 전** 항목 1(기동어 응답)만 1회 재확인한다.
아침엔 정상이었다가 오후에 저하되는 패턴(2026-07 사례가 정확히 이 패턴: 월요일 오후 저하 시작 → 화요일 아침 시연 불가)을 잡기 위함이다.
